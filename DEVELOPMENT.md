# Mr. Robot — руководство для разработчика (RU)

> Читать на других языках: [ENG](./README.md) · [RUS](./README.ru.md) · [PL](./README.pl.md) — это описание проекта для пользователей. Ниже — техническая инструкция по сопровождению приложения.

Локальное приложение-инструментарий (KPI Norms, RS & MP, аудиты и др.). Всё работает в браузере, данные никуда не отправляются. Проект подготовлен для публикации на **GitHub Pages** и установки как **PWA** (работает офлайн, ставится на телефон и компьютер как приложение).

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub с именем `Mr.-Robot-App` (у вас он уже есть).
2. Загрузите содержимое папки `Mr.-Robot-App` (все файлы и подпапки — в корень репозитория).
3. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Откройте сайт: `https://horkiroman4408-cyber.github.io/Mr.-Robot-App/` (ваш адрес уже такой)

Дальше публикация происходит автоматически при каждом push в ветку `main`.

## Как обновлять приложение

1. Меняете нужные файлы: чаще всего `js/app.js`, `css/styles.css`, `index.html`.
2. Commit + push — готово.

Больше ничего поднимать вручную не нужно. Стратегия обновлений — «сеть в первую очередь»: при каждом обычном заходе (переход по ссылке, открытие PWA) приложение всегда грузит свежую версию с сервера, без Ctrl+F5. Кэш используется только когда сети нет — тогда PWA работает офлайн. Баннер **«Dostępna aktualizacja / Zaktualizuj teraz»** вверху экрана появляется только в одном случае: вкладка оставалась открытой, пока вы делали деплой, — нажмите кнопку, и версия сменится сразу, не дожидаясь следующего захода.

Если вы размещаете приложение не через GitHub Actions (например, Pages из ветки без воркфлоу), это тоже работает: свежесть версии обеспечивает сама стратегия «сеть в первую очередь». Ревизию `CACHE_REVISION` в `sw.js` можно не трогать — она влияет только на имя кэша.

Для заметных релизов добавьте запись в начало массива `CHANGELOG_ALL` в `js/changelog.js` (версия, дата, список изменений — это то, что пользователи увидят в разделе «Co nowego») и обновите номер версии в `<title>` в `index.html`.

## Установка как приложение (PWA)

- **Android / Chrome:** открыть сайт → меню ⋮ → «Установить приложение».
- **iPhone / Safari:** «На экран “Домой”».
- **Компьютер (Chrome/Edge):** значок установки в адресной строке.

После установки приложение работает полностью офлайн.

## Нужен ли сервер для работы приложения?

**Нет.** После того как приложение один раз открылось с GitHub Pages (и установилось как PWA), оно работает полностью офлайн — без интернета, без Python и без каких-либо серверов. Всё необходимое (код, стили, библиотеки, иконки) хранится в кэше браузера внутри Service Worker-а. Именно так им и пользуются: открыли сайт → установили → работает всегда.

Локальный HTTP-сервер из инструкции ниже нужен **только вам как разработчику** — чтобы проверить свои изменения перед публикацией на GitHub. Если сервер не запускать, а открыть `index.html` двойным кликом (`file://`), приложение не запустится: браузер запрещает Service Worker-ам и Web Worker-ам работать с локальных файлов. Это ограничение всех браузеров, а не проекта.

## Локальная проверка перед публикацией (для разработки)

```bash
cd Mr.-Robot-App
python3 -m http.server 8000
# откройте http://localhost:8000/
```

## Технические заметки

- Приложение собирает Tailwind CSS прямо в браузере (`js/vendor-tailwind.js`) — классы из разметки работают без сборки проекта.
- Web Worker-ы, обрабатывающие .xlsx, подключают SheetJS через `importScripts('js/cptable.js', 'js/xlsx.js')` — поэтому эти два файла обязаны лежать рядом с приложением.
- Service Worker кэширует только файлы этого приложения и только в рамках его пути (кэш называется `Mr.-Robot-App@/путь/@ревизия`) — другие проекты на домене `github.io` не затрагиваются.
- Данные пользователя (загруженные файлы, настройки, язык) хранятся в IndexedDB браузера и не имеют отношения к кэшу PWA.
